**Problem**

Everyday is time to learn. We did some mistake and I have to learn from. Accept the time and mistake I have done. Acknowledge it, understand it and move on. This is the only mature way to learn and mitigate. 

I have been working on a problem that is redesigning the database so that it satisfies the new needs. I knew I had some mixed responsibilities at the same time. I had to make the new UI work, and I have to make the old system work safety. Also I need to find a way so that old data could be mitigated into the new system as well. 

I jumped into things, printed the schemas of the database, selecting what things are worth to be used in the new system. I had not fixated an idea in my mind. This made me so unfocused, collecting data from here and there. Also I don't have still a connection to the database so I am taking assumptions of what the data means according to it's titles. I have been not very conscious on what I need to do actually. 

I understood that the old data is not beneficial at all in making new records. I have took bad decisions in storing some dates and stuff in the old tables. This was not nice. What I understand now is that the new data is not related at all to the old one. The Category there has a different meaning than the category. Sub Category also is different although it is also present in my data and the old data. I made a new table, that has 70% of the new UI data and 30% I left it in the old database, and this is not useful. It makes things more complicated. 

What I need to do is make the new UI in entire new tables so that they work in a good way. After I build a view for the New UI data, making sure all data needed are sufficient. Then I start asking the question and trying to build a mitigation process for moving the old data (That has only 30% of the new requirement) to the new UI to have a different key. Before I had this image that I will be adding some new tables to complete the data. This is not true. I will be having 2 databases in one database with one database container with some method to copy data from old to new. 

This mistake. I don't know how to describe. It took me like 4 days to understand that a decision that I have not very consciously taken has drained my time without reaching the final expected result. Also, I had not have the clarity to distinguish between a database that has mixed records and another one that has 2 independent records system and a mitigation process between them. 

Maybe I should have been more clear in thinking, and written this unspoken decision, so that we can say in a more prestigious manner that this decision is not right. 

The next step would be to recheck the PROCEDURE into making the new tables completely enough for the new UI. And this is number one task. According to the thinking of Workstream, I should have applied this knowledge here in the same way I forgot about the database when designed the UI, I should have forgotten about the old data when I designed totally and independent of old data the new tables of the new UI. This ability of separating things and delayed thinking of problems is sometimes a great thing.

I am still learning how to separate thinking layers from each other. This thinking problem, it is a problem in the way I think.
