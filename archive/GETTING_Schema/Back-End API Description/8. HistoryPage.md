## Section C: Assumptions / Risks

### Assumptions:

1. **Child pages handle their own data fetching** – Both `PatientHistoryPage` and `DoctorHistoryPage` are responsible for their own API calls, state management, and data rendering.
    
2. **`embedded` prop controls layout** – The child pages likely accept an `embedded={true}` prop to indicate they should render without their own layout wrapper (to avoid duplicate `MainLayout` components).
    
3. **No cross-tab data sharing** – The two history types (patient and doctor) are independent. No data needs to be shared or synchronized between tabs.
    
4. **Tab state is purely local** – The active tab selection is managed entirely in the container component's local state. No need to persist or share this state.
    
5. **No shared search/filters** – If both child pages have search functionality (e.g., search patient, search doctor), the filters are independent and managed within each child page.
    

### Risks:

1. **Double data fetching** – If both child pages fetch data on mount (not on tab activation), switching tabs may not trigger fresh data loads. However, if data is stale when returning to a tab, users may be confused.
    
2. **Performance** – Depending on the tab implementation (Material-UI Joy tabs), both child pages may render simultaneously even when inactive. This could cause:
    
    - Unnecessary API calls for inactive tabs
    - Increased memory usage
    - Consider lazy loading or conditional rendering based on active tab
3. **No shared context** – If patient and doctor history ever need to cross-reference (e.g., "show all incidents involving this patient and this doctor"), the current container provides no mechanism for that. Each tab operates in isolation.
    
4. **Duplicate navigation** – If users frequently switch between patient and doctor history, the container page should ensure smooth transitions without re-mounting child components unnecessarily.
    
5. **Unclear active state** – Users may not immediately recognize which tab is active if visual indicators are subtle. Ensure clear tab highlighting.
    
6. **No breadcrumb context** – If child pages include navigation (e.g., "View incident details"), the container page doesn't provide breadcrumb or navigation history context.
