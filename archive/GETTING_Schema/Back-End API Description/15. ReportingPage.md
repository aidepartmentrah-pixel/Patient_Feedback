## Section C: Assumptions, Open Questions, and Risks

### C1. Assumptions

#### Report Definitions
1. **Monthly Report**: Covers incidents received within calendar month boundaries (1st to last day).
2. **Seasonal Report**: Covers either:
   - **Trimester**: 4-month periods (Jan-Apr, May-Aug, Sep-Dec)
   - **Quarter**: 3-month periods (Q1=Jan-Mar, Q2=Apr-Jun, Q3=Jul-Sep, Q4=Oct-Dec)
3. **HCAT Domain**: Assumed to be the `domain_id` field from Classification taxonomy (reused from InvestigationPage, TableView).
4. **Detailed Mode**: Displays row-level complaints with full incident details.
5. **Numeric Mode**: Displays aggregated statistics grouped by domain, category, severity, department.
6. **Threshold**: User-specified integer value applied uniformly to all HCAT domains for seasonal reports.

#### Data Scope
7. **Open vs Closed Complaints**: Both are included in reports unless explicitly filtered by `status` parameter.
8. **Closed Complaints**: Only counted in aggregations if `closure_date` is within report period.
9. **Organizational Filters**: Hierarchical filtering allows selection at any level (building → idara → dayra → qism).
10. **Patient Privacy**: Patient identifiers (MRN) are partially masked in exports (`MRN-***789`) unless `include_patient_identifiers=true` (restricted to authorized roles).

#### Export Behavior
11. **PDF Export**: Includes formatted tables, charts (if enabled), bilingual headers, hospital branding, timestamp, filter summary.
12. **CSV Export**: Plain-text tabular data with headers in selected language; patient identifiers masked by default.
13. **Bulk Export**: Generates one summary file per department, packaged as ZIP archive.
14. **File Retention**: Exported files expire after 24 hours and are purged from server storage.
15. **Audit Logging**: All export actions are logged with user ID, timestamp, filters applied, file size.

#### Performance
16. **Pagination**: Applied to detailed complaint lists (default 50, max 500 per page).
17. **Monthly Reports**: Expected to handle up to 10,000 complaints per month without performance degradation.
18. **Seasonal Reports**: Expected to aggregate up to 40,000 complaints per trimester.
19. **Bulk Exports**: May trigger background job for >50 departments to avoid request timeout.

---

### C2. Open Questions

#### Report Scope and Business Rules
1. **HCAT Definition**: Is HCAT a formal clinical standard (e.g., WHO Patient Safety Taxonomy), or hospital-specific? Should API documentation reference official HCAT specification?
2. **Trimester vs Quarter**: Which seasonal period is authoritative? Can users select both, or is one enforced?
3. **Threshold Source**: Is threshold value:
   - User-defined per report (as assumed)?
   - Policy-defined per domain (stored in settings)?
   - Both (user can override policy default)?
4. **Threshold Exceedance**: Does exceeding threshold trigger automatic alerts, escalations, or governance notifications?
5. **Trend Direction**: How is "increasing", "stable", "decreasing" calculated? Comparison to prior trimester, same trimester last year, or 12-month rolling average?
6. **Open Complaints in Reports**: Should open complaints be:
   - Included in monthly/seasonal counts?
   - Flagged separately in exports?
   - Excluded from closure time calculations?

#### Data Consistency
7. **Complaint Received Date vs Incident Date**: Which date determines report inclusion (received_date assumed)?
8. **Multi-Department Incidents**: If complaint involves multiple departments (issuing_dept_id ≠ dayra_id), which department "owns" it for bulk export?
9. **Retrospective Edits**: If complaint classification changes after report generation, are historical reports recalculated or frozen?
10. **Data Completeness**: What happens if complaint is missing domain_id or category_id? Is it excluded, or shown as "Unclassified"?

#### Export Requirements
11. **PDF Format**: What level of detail is required?
    - Executive summary only?
    - Full complaint tables with patient identifiers?
    - Charts and visualizations mandatory?
12. **Bulk Export Scope**: Does bulk export include:

### C3. Identified Risks

#### Data Privacy and Security
1. **Patient Identifier Leakage**: CSV exports may inadvertently expose full MRNs if masking logic fails or is bypassed.
2. **Unauthorized Export Access**: Download URLs may be accessible without authentication if not properly secured (must validate user session on every download).
3. **File Retention Violations**: Exported files containing patient data must be purged after 24 hours to comply with data retention policies; failure to purge = regulatory risk.
4. **Email Transmission Risk**: Bulk export email notifications may expose download links in unencrypted email; recommend secure file transfer portal instead.

#### Report Accuracy
5. **Filter Inconsistency**: If monthly detailed view and monthly numeric view use different filter logic, aggregated counts may not match row-level counts.
6. **Date Boundary Issues**: Complaints received at 23:59 on month-end may be miscategorized due to timezone/time-of-day handling.
7. **Aggregation Errors**: Derived fields (`exceeds_threshold`, `threshold_ratio`) may produce incorrect values if threshold=0 or null.
8. **Stale Data**: If reports are cached, they may not reflect real-time updates (e.g., complaint status changed from open to closed mid-report).

#### Performance Bottlenecks
9. **Large Monthly Reports**: Fetching 10,000+ complaints without pagination may exceed request timeout or memory limits.
10. **PDF Generation Overhead**: Rendering complex charts and tables in PDF may take >30 seconds, blocking user interface.
11. **Concurrent Bulk Exports**: Multiple users triggering bulk exports simultaneously may exhaust server resources (CPU, memory, disk I/O).
12. **Database Query Complexity**: Seasonal HCAT analysis with multiple GROUP BY clauses (domain, category, department) may slow down on large datasets without proper indexing.

#### Export File Management
13. **Disk Space Exhaustion**: Accumulated export files (especially bulk ZIPs) may fill server disk if purge job fails.
14. **Filename Collisions**: If two users export same report at same time, filename may collide unless export_id is unique and timestamped.
15. **Expired File Access**: User may attempt to download file after 24-hour expiration, causing 404 error without clear explanation.

#### Business Logic Gaps
16. **Threshold Interpretation**: Unclear whether threshold is "alert if ≥ threshold" or "alert if > threshold" (edge case ambiguity).
17. **Multi-Domain Complaints**: If complaint is classified under multiple domains (e.g., Medication + Diagnosis), it may be double-counted in seasonal HCAT analysis.
18. **Trend Calculation Failure**: If prior period has zero complaints, trend_direction may be undefined or incorrectly calculated.

#### Governance and Compliance
19. **Audit Log Completeness**: If export action logging fails (e.g., database write error), export may succeed but leave no audit trail.
20. **Unauthorized Role Access**: If role-based access control is not enforced on `/api/reports/export/pdf`, unauthorized users may generate governance-level reports.
21. **Report Tampering**: Downloaded PDFs/CSVs may be edited externally and re-submitted as "official" reports; digital signatures recommended.
22. **Regulatory Compliance**: Hospital may be required to retain reports for 7+ years; 24-hour expiration conflicts with archival requirements.

#### User Experience
23. **Export Timeout**: Long-running PDF generation may timeout on client side, causing user to re-trigger duplicate exports.
24. **No Progress Feedback**: Bulk export (async) provides no intermediate progress updates; user cannot estimate completion time.
25. **Missing Bilingual Support**: If user selects Arabic language but some labels are missing _ar translations, export may display English labels inconsistently.
